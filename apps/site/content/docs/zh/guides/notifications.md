## 个人接收端点

每个系统用户在账户页维护自己的接收端点。支持邮件、PushDeer、Bark、ntfy、Telegram、
Discord、Slack、Microsoft Teams、飞书、钉钉和企业微信；飞书/钉钉支持可选机器人
签名。凭据加密保存且 API 不返回，编辑时留空秘密字段会保留原值。

用户初始拥有基于账户邮箱的有效邮件端点。补齐只针对没有邮件端点的用户，保留后续
启用/禁用选择。产品保存策略，不保存个人地址、设备令牌或 webhook 秘密。

## 继承

按事件产品的**租户 → 工单当前团队 → 产品**解析，不合并其他关联团队。子范围可以
完整覆盖父策略、本地禁用或新增策略。删除覆盖恢复继承，禁用遮蔽父策略；仍有覆盖
的根策略不能删除。系统团队不参与此链。

## 规则、要求与事件

规则选择事件、通道和接收者：当前处理人、当前团队、范围内所有客服、指定团队或客服。
要求为选定事件/人员强制指定通道，并直接参与投递。两者都只解析为事件产品当前有效
客服，重叠策略按接收端点去重。缺少选中/必需通道写入失败日志，不静默跳过；合规
检查使用相同解析器。

事件为 `ticket_created`、`ticket_assigned`、`ticket_reassigned`、
`ticket_escalated`、`ticket_expiring`、`customer_replied` 和 `ticket_closed`。
手动静默关闭只跳过客户邮件，不跳过工作人员通知。

## 配置与检查

租户/产品页及范围内团队页提供策略与合规检查。产品预览可选团队查看完整继承链。
TeamAdmin 仅管理自己团队，ProductAdmin 管理已分配产品及产品团队。所有用户只
维护自己的目的端点。保存端点的测试属于个人操作；邮件测试需选可见产品，使用其
外发提供商。

邮件端点通过事件产品的外发提供商发送。Webhook 或提供商接受不证明人员已收到，
排查时结合通知日志与接收服务。
