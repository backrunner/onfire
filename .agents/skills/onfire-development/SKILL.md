# OnFire Development

Use the repository's current architecture and written requirements to make production-safe changes without erasing unrelated work.

## Start

1. Read `/AGENTS.md` and `/.agents/STATUS.md` completely.
2. Read `/.agents/REQUIREMENTS.md` for behavior and RBAC decisions.
3. Read only the relevant reference:
   - UI or interaction: [design.md](references/design.md)
   - API, database, Workers, email, or AI: [engineering.md](references/engineering.md)
4. Inspect `git status` and preserve all changes outside the current task.

## Implement

- Follow established route, scope-helper, service, and shadcn patterns before adding abstractions.
- Enforce both permission and data scope in APIs. Treat UI checks as presentation only.
- Preserve tenant integrity independently of role scope: globally visible records still cannot be associated across tenants.
- Keep lifecycle permissions separate from settings permissions when a lower role must configure an existing resource without creating or deleting it.
- Keep edits inside the affected module and update English and Chinese locale keys together.
- Generate a new Drizzle migration for schema changes and apply it locally.
- Use current official provider documentation and installed Workers types for external protocols.
- Keep `CloudflareEnv` generated by Wrangler. Use the value-free `wrangler.types.env` for deterministic secret names in CI and regenerate after config changes.
- Keep SLA timers state-aware through the shared helper; never duplicate overdue predicates in list or dashboard queries.
- Treat email preview/delivery, MIME normalization, and AI provider protocols as shared contracts with failure-path tests.
- Configure Turnstile site key and secret as a pair; protected ToC mutations fail closed when the widget cannot issue a token.
- Update `.agents/STATUS.md` and `AGENTS.md` when a durable requirement or prerequisite changes.

## Verify

Run the CI gates in order:

```bash
pnpm install --frozen-lockfile
pnpm cf-typegen --check
pnpm lint
pnpm test
pnpm build:worker
```

For first-deploy, schema, binding, or dependency work, also check Drizzle metadata, apply all migrations to a fresh local D1 directory, run Wrangler deploy dry-run/startup profiling, and run `pnpm audit --prod`. Remove the generated startup profile afterwards. These checks never authorize remote mutations.

Use Playwright for changed ToB/ToC flows at desktop and mobile widths. Inspect screenshots for overflow, unequal sibling height, empty states, form spacing, popover clipping, and dark-mode contrast.

## Deliver

- Report changed behavior, migrations, verification, and external setup still required.
- Use `xxx(comp): desc` only when the user asks for a commit.
- Never deploy, migrate remote D1, create remote Vectorize indexes, or commit without explicit authorization.
